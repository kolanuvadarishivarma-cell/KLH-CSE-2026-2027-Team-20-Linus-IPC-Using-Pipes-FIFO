# Viva Voce Questions & Answers: Copy-on-Write Memory Demonstrator

**Course**: Operating Systems and System Programming (OSSP)

---

### Q1. What is Copy-on-Write (COW)?
**Answer**:  
Copy-on-Write is a resource-management technique used by modern operating systems where processes initially share the same physical memory pages with read-only permissions. A private duplicate copy of a page is only created when one of the processes attempts to write to it.

---

### Q2. What does the `fork()` system call do in Linux?
**Answer**:  
`fork()` duplicates the calling process to create an exact child process. The child gets a copy of the parent's file descriptors, environment variables, registers, and memory mappings, but receives a unique Process ID (PID). In the parent, `fork()` returns the child's PID; in the child, it returns `0`.

---

### Q3. What is a Process ID (PID)?
**Answer**:  
A Process ID is a unique positive integer assigned by the Linux kernel to each active process. It is used to identify, monitor, and signal processes via tools like `kill`, `ps`, and `top`.

---

### Q4. What happens immediately after `fork()` with respect to physical memory?
**Answer**:  
Physical memory pages are **not** copied immediately. Instead, the Linux kernel clones the parent’s page table entries and marks all shared pages as **Read-Only** in both parent and child page tables. Both processes continue to map to the identical physical RAM frames.

---

### Q5. Why does the child initially observe the parent's memory value (100)?
**Answer**:  
Because both the parent and child virtual page tables point to the exact same physical frame that was populated by the parent before the `fork()` call. Since neither process has written to it yet, the data read from that physical frame is identical (`100`).

---

### Q6. What is a Page Fault?
**Answer**:  
A page fault is an exception/trap generated by the CPU's Memory Management Unit (MMU) when a program accesses a page that is not currently mapped into physical memory or when an operation violates page permissions (such as attempting to write to a page marked Read-Only).

---

### Q7. When does Linux copy a COW page?
**Answer**:  
Linux copies a COW page when a process attempts to execute a write instruction (e.g. `*var = 200`) on a page marked Read-Only. The CPU raises a write-protection page fault, trapping into the kernel function `do_wp_page()`. The kernel allocates a fresh physical frame, copies the 4KB page content, updates the writer's page table entry with Read-Write permissions, and returns to user space to resume the write instruction.

---

### Q8. What is the difference between Virtual Memory and Physical Memory?
**Answer**:  
- **Virtual Memory**: An abstraction provided by the OS and hardware MMU giving each process the illusion of having a contiguous, private address space (e.g., `0x0000...` to `0x7fff...`).
- **Physical Memory**: The actual hardware semiconductor RAM chips installed in the computer. Virtual addresses are dynamically mapped to physical frames via multi-level page tables.

---

### Q9. What is the purpose of `waitpid()`?
**Answer**:  
`waitpid()` blocks the calling parent process until a specific child process terminates or changes execution state. It allows the parent to collect the child's exit status (`WIFEXITED`, `WEXITSTATUS`) and releases the child's process table entry, preventing the child from becoming a **zombie process**.

---

### Q10. What is the purpose of `mmap()`?
**Answer**:  
`mmap()` is a POSIX system call that creates a new memory mapping in the virtual address space. It can map files directly into memory for efficient I/O, or allocate raw pages from the kernel using anonymous memory (`MAP_ANONYMOUS`).

---

### Q11. What is the difference between `MAP_PRIVATE` and `MAP_SHARED` in `mmap()`?
**Answer**:  
- `MAP_PRIVATE`: Modifications to the mapped region are private to the calling process and use Copy-on-Write. They are not visible to other processes.
- `MAP_SHARED`: Modifications are shared among all processes mapping the same region and are synced back to the underlying file (if file-backed).

---

### Q12. What are the key advantages of Copy-on-Write?
**Answer**:  
1. **Instantaneous Process Creation**: `fork()` completes in sub-milliseconds without waiting for gigabytes of memory to copy.
2. **Memory Conservation**: Shared libraries (`libc.so`) and read-only code segments are loaded once and shared across hundreds of processes.
3. **Optimized `fork() + execve()`**: When a shell forks to run a command (like `ls` or `grep`), the child immediately calls `execve()`, which replaces the entire memory image. COW ensures zero memory pages are unnecessarily copied.

---

### Q13. Why does Copy-on-Write operate at page granularity rather than variable granularity?
**Answer**:  
The CPU MMU and Translation Lookaside Buffer (TLB) maintain protection and presence bits at the page level (typically 4096 bytes on x86_64, 16384 bytes on Apple Silicon ARM64). The hardware cannot enforce write permissions at the granularity of a 4-byte integer.

---

### Q14. What kernel function handles the Copy-on-Write write fault in Linux?
**Answer**:  
In the Linux kernel virtual memory subsystem (`mm/memory.c`), the function `do_wp_page()` (Write-Protect Page) is called by the page fault handler when a write is attempted on a shared read-only private page. It handles allocation of a new `struct page`, page copying via `copy_user_highpage()`, and PTE updating.
